# EmbeddedGUI_Lite v2

Ультралёгкая графическая библиотека для монохромных OLED-дисплеев (SSD1306, SH1106) на Arduino-совместимых платах: **один кадровый буфер ровно 1 КБ для 128×64, ноль динамической памяти, ноль внешних зависимостей** (только штатный `Wire`).

```cpp
#include <EmbeddedGUI.h>

EmbeddedGUI_OLED<128, 64> gui;               // объект GUI (буфер 1 КБ внутри)

void setup() { gui.begin(); }                // Wire + инициализация дисплея

void loop() {
  gui.clear();                               // очистить буфер
  gui.text(0, 0, F("Hello, OLED!"));         // рисуем
  gui.update();                              // отправить кадр
}
```

## 1. Что изменилось по сравнению с v1

**Главная проблема v1.** `CanvasBuffer` (1 КБ) рисовал в свой буфер, а затем `GfxBackend` копировал кадр в `Adafruit_SSD1306`, у которого есть *собственный* буфер ещё на 1 КБ. На ATmega328P (2 КБ ОЗУ) два буфера съедают всю память, и на стек с переменными ничего не остаётся.

**Решение v2.**

| Было (v1) | Стало (v2) |
|---|---|
| Холст наследовал `Adafruit_GFX`, вывод через `Adafruit_SSD1306` | Своя реализация примитивов и текста, свой драйвер I2C поверх `Wire` |
| Два буфера по 1 КБ (холст + буфер драйвера) | **Один** буфер 1 КБ, который уходит на дисплей напрямую |
| Формат буфера «строки по байтам» → пересчёт в формат дисплея при каждом `drawBitmap` | Буфер сразу в страничном формате SSD1306: конвертации нет |
| 3 объекта на старте (дисплей, холст, бэкенд) + `EmbeddedGUI` | 1 объект: `EmbeddedGUI_OLED<128,64> gui;` |
| Грязные *строки*, отправка через пиксельный `drawBitmap` | Грязные *страницы* (8 строк), отправка сырыми байтами |
| `snprintf`/`vsnprintf` в виджетах (+≈1.5 КБ флеша), `float` в `ProgressBar` | Собственное форматирование чисел, целочисленная математика |
| Массив `_items[8]` в каждом `Screen`, лимит виджетов | Связный список (2 байта на виджет), лимита нет |
| Очередь событий, FPS-лимитер, `Theme`, режим RGB565, бэкенды GFX/U8g2 | Убрано: интерфейс стал короче, ОЗУ — меньше (см. [§13](#13-миграция-с-v1)) |
| Динамической памяти нет | Динамической памяти нет (и нигде нет `new`/`malloc`/`std::function`/`String`) |

## 2. Установка и подключение

**Установка.** Скопируйте папку `EmbeddedGUI_Lite` в `Documents/Arduino/libraries/` (или добавьте zip через *Скетч → Подключить библиотеку → Добавить .ZIP*). В PlatformIO: положите папку в `lib/` проекта. Достаточно одного `#include <EmbeddedGUI.h>`.

**Подключение OLED (I2C):**

| OLED | Arduino Uno/Nano | ESP32 (по умолч.) | ESP8266 (NodeMCU) |
|---|---|---|---|
| GND | GND | GND | GND |
| VCC | 5V или 3.3V (по модулю) | 3.3V | 3.3V |
| SDA | A4 | GPIO21 | D2 (GPIO4) |
| SCL | A5 | GPIO22 | D1 (GPIO5) |

Адрес по умолчанию `0x3C`. Если дисплей не находится (`begin()` вернул `false`), попробуйте `0x3D`: `EmbeddedGUI_OLED<128,64> gui(0x3D);`. Если адрес неизвестен, запустите любой I2C-сканер.

**Варианты объявления:**

```cpp
EmbeddedGUI_OLED<128, 64> gui;                          // SSD1306 128x64, адрес 0x3C
EmbeddedGUI_OLED<128, 32> gui;                          // SSD1306 128x32
EmbeddedGUI_OLED<128, 64> gui(0x3D);                    // другой адрес
EmbeddedGUI_OLED<128, 64> gui(0x3C, EGUI_SH1106);       // SH1106 (1.3" модули)
EmbeddedGUI_OLED<128, 64> gui(0x3C, EGUI_SSD1306, Wire1); // вторая шина I2C
```

> Объявляйте `gui` **глобально**: тогда буфер лежит в `.bss`, а не на стеке (на AVR 1 КБ на стеке — это почти гарантированный вылет).

## 3. Архитектура

### 3.1. Слои

```
┌─────────────────────────────────────────────────────────────┐
│ Ваш скетч                                                   │
├─────────────────────────────────────────────────────────────┤
│ EmbeddedGUI_OLED<W,H>     «всё в одном»: буфер + драйвер    │
│   └─ EmbeddedGUI          update(), draw(widget), экраны    │
│        ├─ CanvasBuffer    примитивы, текст, dirty-страницы  │
│        │                  (формат буфера = формат SSD1306)  │
│        ├─ ViewportManager стек экранов (отложенная навиг.)  │
│        │    └─ Screen     список виджетов, фокус, события   │
│        │         └─ UIWidget → Label/Button/ProgressBar/... │
│        └─ DisplayBackend  интерфейс: begin() + present()    │
│             └─ SSD1306Backend  I2C поверх Wire (SSD1306/SH1106)
└─────────────────────────────────────────────────────────────┘
```

| Файл | Назначение |
|---|---|
| `EmbeddedGUI.h/.cpp` | Фасад: `EmbeddedGUI`, шаблон `EmbeddedGUI_OLED<W,H>`, `DebouncedButton` |
| `CanvasBuffer.h/.cpp` | Буфер, примитивы, текст, форматирование чисел, учёт «грязных» страниц |
| `EGUI_Font5x7.h` | Шрифт 5×7 (ASCII 32..126), 475 байт во флеше |
| `DisplayBackend.h` | Интерфейс вывода кадра (для своих дисплеев) |
| `SSD1306Backend.h/.cpp` | Драйвер SSD1306/SH1106 по I2C |
| `Widgets.h/.cpp` | `UIWidget`, `Label`, `Button`, `ProgressBar`, `DynamicGraph` |
| `ViewportManager.h/.cpp` | `Screen` и стек переходов |
| `EmbeddedGUI_Config.h` | Константы времени компиляции |

### 3.2. Формат буфера (почему он один)

SSD1306 хранит изображение **страницами**: страница — это 8 строк пикселей, а байт — 8 пикселей одного столбца (младший бит сверху).

```
индекс байта = (y >> 3) * width + x
бит в байте  =  y & 7

        x=0  x=1  x=2 ...  x=127
стр.0   [b]  [b]  [b]  ...  [b]    ← y = 0..7     (младший бит = y=0)
стр.1   [b]  [b]  [b]  ...  [b]    ← y = 8..15
 ...
стр.7   [b]  [b]  [b]  ...  [b]    ← y = 56..63
```

Холст хранит кадр **ровно в этом формате**. Поэтому:

* память = `width × height / 8` = 1024 байта для 128×64;
* на дисплей страница уходит одним куском `width` байт, без пересчёта пикселей;
* никакой второй копии кадра нет: драйвер читает прямо из буфера холста (в I2C-транзакцию `Wire.write(ptr, n)` отдаётся указатель в этот же буфер).

Побочный эффект: заливка прямоугольника — это побайтовые маски по страницам (`fillRect` работает в разы быстрее попиксельного цикла), а текст 5×7 накладывается столбцами, сдвинутыми на `y & 7` в две соседние страницы.

### 3.3. Поток данных одного кадра

```
loop()
  gui.clear()                 → memset буфера, все страницы «грязные»
  gui.text()/rect()/draw(w)   → пишут в буфер, помечают затронутые страницы
  gui.update()
     ├─ (если активен экран) навигация → анимации → перерисовка экрана
     ├─ нет грязных страниц?  → выход, шина молчит
     └─ backend.present(buffer, firstDirty, lastDirty)
           для каждой страницы: [0xB0|стр, колонка] + width байт чанками
```

Грязные страницы хранятся как диапазон `[первая..последняя]`: это 2 байта, а не битовая маска/второй буфер.

## 4. Модель памяти

**Правила:**

1. Нигде нет `new`/`malloc`/`delete`/`String`/`std::function`/`std::vector`. Фрагментации кучи быть не может.
2. Весь объём известен на этапе компиляции. Буфер — член шаблона `EmbeddedGUI_OLED<W,H>`; виджеты и экраны создаёте вы (глобально или членами своих `Screen`), библиотека хранит только указатели.
3. Строки во флеше: `F("...")` не занимает ОЗУ на AVR и принимается всеми методами (`text`, `Label`, `Button`).
4. `printf` не используется: числа форматируются собственным кодом (экономия ≈1.5 КБ флеша и стека).
5. Виртуальные деструкторы убраны намеренно: объекты статические, удаление через базовый класс не поддерживается (деструкторы защищённые).

**Оценка ОЗУ на AVR (ATmega328P).** Числа получены подсчётом полей классов (указатель = 2 байта), а не измерением на плате. Точные значения смотрите в отчёте компилятора («Global variables use … bytes») или командой `avr-size`.

| Объект | ОЗУ, байт |
|---|---|
| `EmbeddedGUI_OLED<128,64>`: буфер | 1024 |
| …служебные поля холста, ядра, стека экранов, драйвера | ≈ 40 |
| `Label` (при `EGUI_LABEL_CAPACITY` = 20) | ≈ 36 |
| `Button` | ≈ 24 |
| `ProgressBar` | ≈ 28 |
| `DynamicGraphT<N>` | ≈ 26 + 2·N |
| `Screen` | ≈ 9 |
| Таблицы виртуальных функций (на AVR как правило лежат в ОЗУ) | десятки байт суммарно |
| Библиотека `Wire` (буферы TWI) | порядка 150 (не наша, но учитывайте) |

Минимальный скетч (`01_MinimalUno`) по этой оценке укладывается примерно в **1.2 КБ** ОЗУ из 2 КБ: остаётся ≈ 800 байт на стек и ваши переменные. С `Adafruit_SSD1306` + буфером холста v1 было бы 2 КБ только под два кадра.

**Если памяти всё равно мало:**

* используйте `128×32` (512 байт): `EmbeddedGUI_OLED<128,32>`;
* уменьшите `EGUI_LABEL_CAPACITY` (по умолчанию 20), `EGUI_MAX_SCREEN_DEPTH` (по умолчанию 4);
* уменьшите ёмкость графика `DynamicGraphT<N>`;
* строки только через `F()`.

## 5. Справочник API

### 5.1. `EmbeddedGUI_OLED<W, H>` / `EmbeddedGUI`

| Метод | Описание |
|---|---|
| `EmbeddedGUI_OLED(addr=0x3C, chip=EGUI_SSD1306, TwoWire& wire=Wire)` | Конструктор. Ничего не трогает в железе. |
| `bool begin(bool initWire = true)` | Инициализирует шину и дисплей, очищает буфер и экран. `false` — дисплей не отвечает. `initWire=false`, если шину вы настроили сами. |
| `void update()` | **Единственный метод вывода.** Отправляет изменённые страницы. В режиме экранов предварительно выполняет навигацию, анимации и перерисовку. Если ничего не менялось — шина не используется. |
| `void invalidate()` | Принудительно отправить весь буфер при следующем `update()`. |
| `void draw(UIWidget& w)` | Вызывает `w.update(millis())` и `w.draw(...)`. Режим «рисую сам». |
| `bool setScreen(Screen&)` | Корневой экран (или замена текущего). |
| `bool push(Screen&)` / `bool pop()` / `void popToRoot()` | Навигация (отложенная, см. [§7](#7-экраны-и-навигация)). |
| `Screen* screen()` | Текущий экран. |
| `bool handleEvent(InputEvent)` | Подать событие ввода активному экрану. Только из `loop()`, не из прерываний. |
| `setContrast(uint8_t)`, `setPower(bool)`, `setInverted(bool)`, `setFlipped(bool)` | Управление дисплеем. |
| `driver()` | Доступ к `SSD1306Backend` (например, `setColumnOffset`). |
| `lastFlushMicros()`, `flushCount()` | Диагностика: время последней отправки, число отправок. |

Все методы холста (ниже) доступны прямо у `gui`.

### 5.2. Холст (`CanvasBuffer`)

Цвет: `EGUI_BLACK` (0, погасить), `EGUI_WHITE` (1, зажечь, значение по умолчанию), `EGUI_INVERT` (2, инвертировать пиксели под фигурой). Все операции безопасно отсекаются по границам экрана; координаты могут быть отрицательными.

| Метод | Описание |
|---|---|
| `clear(color = BLACK)` | Заливка всего буфера |
| `pixel(x, y, color)` / `getPixel(x, y)` | Точка |
| `hLine(x, y, w)`, `vLine(x, y, h)`, `line(x0, y0, x1, y1)` | Линии (Брезенхем) |
| `rect(x, y, w, h)`, `fillRect(x, y, w, h)` | Прямоугольник |
| `roundRect(x, y, w, h, r)`, `fillRoundRect(...)` | Со скруглением |
| `circle(cx, cy, r)`, `fillCircle(cx, cy, r)` | Окружность |
| `bitmap(x, y, bmp, w, h)` | Картинка из **PROGMEM**: построчно, MSB первым, `(w+7)/8` байт на строку (формат Adafruit `drawBitmap` / вывод LCD Assistant); рисуются только единичные биты |
| `text(x, y, "str" \| F("str"), size=1, color)` | Текст 5×7, ячейка 6×8, `size` — целый множитель; `\n` — перенос. Возвращает X после последнего символа. |
| `number(x, y, long, size, color)` | Целое число |
| `numberF(x, y, float, decimals, size, color)` | Дробное, `decimals` ≤ 4 (работает на AVR, где `printf("%f")` недоступен) |
| `CanvasBuffer::textWidth(str, size)` | Ширина первой строки текста |
| `width()`, `height()`, `buffer()`, `bufferSize()` | Информация |

Пример «склейки» текста через возвращаемое значение:

```cpp
int16_t x = gui.text(0, 0, F("T="));
x = gui.numberF(x, 0, temperature, 1);
gui.text(x, 0, F(" C"));
```

Типичные приёмы с `EGUI_INVERT`: выделенная строка меню (`fillRect(..., INVERT)` поверх текста), мигающий курсор, текст на изменяющемся фоне.

## 6. Виджеты

Виджет — объект с методами `update(nowMs)` (анимации), `draw(canvas)`, `onEvent(e)`. Вы создаёте его сами; в режиме «рисую сам» вызываете `gui.draw(widget)`, в режиме экранов добавляете в `Screen`. Любое изменение состояния ставит флаг *dirty* (в режиме экранов от него зависит, перерисовывать ли кадр).

Общие методы: `setPosition(x,y)`, `setSize(w,h)`, `setVisible(bool)`, `x()/y()/width()/height()`.

### `Label` — текст

```cpp
Label title(0, 0, 128, F("Temperature"), 1);   // x, y, ширина области, текст, размер
Label value(0, 16, 128, "", 2);
value.setAlign(Label::Center);
value.setFloat(23.47f, 1);                     // "23.5"
value.setInt(42);
value.setText("OK");                           // копируется во внутренний буфер
value.setText(F("Ошибка"));                    // F(): копируется из флеша
```

Текст копируется во внутренний буфер `EGUI_LABEL_CAPACITY` (по умолчанию 20 байт); длиннее — обрезается. Повторная установка того же значения **не** вызывает перерисовки.

### `Button` — кнопка

```cpp
static void onOk(void* ctx) { /* ... */ }
Button ok(0, 48, 60, 16, F("OK"));
ok.setOnClick(onOk);          // функция + необязательный void* ctx; без std::function
```

Реагирует на `InputEvent::Select`. В фокусе рисуется двойной рамкой (видно и на монохроме), при нажатии на 120 мс (`EGUI_BUTTON_FLASH_MS`) заливается. Callback можно безопасно использовать для навигации (`gui.push(...)`): переходы отложенные. Текст кнопки не копируется — строка должна жить дольше кнопки (литерал и `F()` подходят).

### `ProgressBar` — прогресс с плавной анимацией

```cpp
ProgressBar bar(0, 52, 128, 12);
bar.setRange(0, 1000);        // по умолчанию 0..100 (значения int16_t)
bar.setValue(730);            // полоса плавно доедет до 73%
bar.showPercent(true);        // «73%» по центру (нужна высота ≥ 11)
bar.setSmooth(false);         // мгновенно, без анимации
```

Реализован на целых числах: положение хранится как доля 0..65535, сглаживание экспоненциальное с постоянной `EGUI_PROGRESS_SMOOTH_MS` (150 мс) и не зависит от частоты кадров. Текст процентов рисуется цветом `EGUI_INVERT`: он автоматически чёрный на заполненной части и белый на пустой.

### `DynamicGraph` / `DynamicGraphT<N>` — график реального времени

```cpp
DynamicGraphT<64> graph(0, 0, 128, 40);   // 64 отсчёта = 128 байт ОЗУ
graph.setRange(0, 1023);                  // фиксированный диапазон (по умолчанию — автомасштаб)
graph.showGrid(true);
graph.pushSample(analogRead(A0));         // O(1), кольцевой буфер
```

Если в окне больше точек, чем пикселей по ширине, показывается последний отрезок. Для работы с внешним массивом есть конструктор `DynamicGraph(x,y,w,h, int16_t* storage, capacity)`.

### Свой виджет

```cpp
class Dot : public UIWidget {
public:
  Dot(int16_t x, int16_t y) : UIWidget(x, y, 5, 5) {}
  void draw(CanvasBuffer& c) override { c.fillCircle(_x, _y, 2); }
};
```

Для интерактивных виджетов переопределите `isFocusable()` и `onEvent()`.

## 7. Экраны и навигация

Для приложений с несколькими «страницами» (главная → настройки → график) используйте `Screen`. Это необязательный слой: в простых проектах он ни ОЗУ, ни флеша не занимает, кроме 12 байт поля стека в `EmbeddedGUI`.

```cpp
class MainScreen : public Screen {
public:
  MainScreen() : title(0, 0, 128, F("Main")), open(0, 48, 128, 16, F("Settings")) {
    add(title); add(open);           // порядок добавления = порядок отрисовки и обхода фокуса
  }
  void onUpdate(uint32_t nowMs) override { /* опрос датчиков без delay() */ }
  Label title; Button open;
} mainScreen;

static void goSettings(void*) { gui.push(settingsScreen); }

void setup() {
  gui.begin();
  mainScreen.open.setOnClick(goSettings);
  gui.setScreen(mainScreen);
}
void loop() {
  if (btnDown.pressed()) gui.handleEvent(InputEvent::Down);
  if (btnOk.pressed())   gui.handleEvent(InputEvent::Select);
  if (btnBack.pressed()) gui.handleEvent(InputEvent::Back);
  gui.update();                      // всё остальное делает update()
}
```

**Хуки `Screen`:** `onEnter()`, `onExit()`, `onUpdate(nowMs)` (вызывается каждый цикл, не блокируйте), `onDraw(canvas)` (рисование фона под виджетами), `onEvent(e)` (по умолчанию: событие — виджету в фокусе; `Up/Left` и `Down/Right` — смена фокуса с заворачиванием; `Back` — возврат на предыдущий экран).

**Навигация отложенная.** `push/pop/replace` лишь запоминают запрос и применяются в начале следующего `update()`, поэтому их безопасно вызывать из callback'а кнопки. Запрос один: если за цикл вызвано несколько, выполнится последний. Глубина стека — `EGUI_MAX_SCREEN_DEPTH` (4).

**События ввода.** `InputEvent`: `Up, Down, Left, Right, Select, Back`. Источником может быть что угодно (кнопки, энкодер, UART). `DebouncedButton(pin)` — неблокирующий антидребезг: `begin()` настраивает пин (`INPUT_PULLUP`, активный LOW), `pressed()` вернёт `true` один раз на нажатие.

**Режим экранов vs «рисую сам».** Выберите один: когда активен `Screen`, он сам очищает и перерисовывает буфер, поэтому ваши `gui.clear()`/`gui.text()` перед `update()` будут затёрты. Чтобы нарисовать что-то поверх экрана, используйте `Screen::onDraw()` (под виджетами) либо отключите автоочистку `setAutoClear(false)` и рисуйте в `onDraw`.

Перерисовка экрана происходит только если изменился какой-либо виджет или экран (`Screen::invalidate()`); на статичном экране шина молчит.

## 8. Вывод на дисплей: бэкенды и протокол I2C

### 8.1. Что делает `SSD1306Backend`

Инициализация (`begin()`): проверка, что на адрес отвечает устройство (иначе `false`); `Wire.setClock(EGUI_I2C_CLOCK)` (400 кГц); последовательность команд: выкл → тактирование → мультиплексирование `height-1` → смещение → **charge pump** → **страничная адресация** → ориентация (`0xA1/0xC8`) → COM-пины (`0x12` для 64 строк, `0x02` для 32) → контраст → pre-charge → VCOMH → вкл.

Отправка кадра (`present`) для каждой грязной страницы `p`:

1. Одна транзакция: `[0x00 (команды)] [0xB0|p] [младшие 4 бита колонки] [0x10 | старшие]`.
2. Данные порциями по `EGUI_I2C_CHUNK` байт: `[0x40 (данные)] [N байт прямо из буфера холста]`.

Порция ограничена буфером `Wire` (32 байта на AVR): 1 управляющий байт + 30 данных = 31 ≤ 32. На прочих платформах по умолчанию 16 (универсально безопасно, STM32-ядра тоже имеют 32-байтный буфер); при желании увеличьте `EGUI_I2C_CHUNK` до `размер буфера Wire − 1`, если ваше ядро это позволяет (у ESP32/ESP8266 буфер обычно больше 32 байт — сверьтесь с документацией ядра).

Память драйвера — ≈10 байт; **собственного буфера нет**, поэтому `memcpy` не нужен: данные читаются из холста по указателю.

### 8.2. SH1106

Передайте `EGUI_SH1106`: драйвер использует DC-DC-команду SH1106 (`0xAD 0x8B`) и смещение колонок 2 (в SH1106 RAM шириной 132 столбца). Если после `setFlipped(true)` картинка сдвинулась на 2 пикселя, задайте `gui.driver().setColumnOffset(0)`.

### 8.3. Свой бэкенд (SPI, другой контроллер)

Достаточно унаследоваться от `DisplayBackend` и реализовать два метода. Буфер всегда в страничном формате; `buffer + page * width` — начало страницы.

```cpp
class MySpiOled : public DisplayBackend {
public:
  bool begin() override { /* SPI.begin(); reset; init-команды */ return true; }
  void present(const uint8_t* buf, uint8_t first, uint8_t last) override {
    for (uint8_t p = first; p <= last; ++p) {
      /* выбрать страницу p, колонку 0 */
      /* SPI.transfer(buf + p * 128, 128) */
    }
  }
};

MySpiOled spi;
uint8_t mem[CanvasBuffer::requiredBytes(128, 64)];   // глобально
EmbeddedGUI gui(128, 64, mem, spi);                  // то же API, что у EmbeddedGUI_OLED
```

Контроллеры с другим форматом RAM (например, цветные TFT) потребуют конвертации внутри `present()`; данный холст рассчитан на монохромные дисплеи.

## 9. Производительность и частота кадров

Время полного кадра на I2C определяется шиной. Расчёт для 128×64 при 400 кГц, `EGUI_I2C_CHUNK` = 30 (AVR): на страницу 5 байт команд + 138 байт данных с адресами/управляющими = 143 байта; 8 страниц = 1144 байта; 1144 × 9 бит / 400 кГц ≈ **26 мс** плюс накладные расходы START/STOP, итого порядка 27–30 мс, то есть **≈ 35 кадров/с максимум**. При стандартных 100 кГц это ≈ 105 мс (≈ 9 кадров/с). Это **расчёт**, а не измерение; фактическое значение показывает `gui.lastFlushMicros()`.

**Как получить максимум:**

* оставьте 400 кГц (`EGUI_I2C_CLOCK`), если модуль и подтяжки это держат;
* не перерисовывайте, если ничего не менялось: `update()` и так не шлёт чистые страницы, а в режиме экранов не перерисовывает неизменившийся экран;
* перерисовывайте только нужные страницы: не вызывайте `clear()` без необходимости. Если вы обновляете, например, только нижнюю строку, рисуйте поверх (`fillRect(..., EGUI_BLACK)` + `text`), и уйдёт только страница(ы) с этой строкой;
* для «спокойных» интерфейсов ограничьте частоту кадров сами:

```cpp
static uint32_t last = 0;
void loop() {
  readInputs();                         // опрос кнопок/датчиков - без ограничений
  if (millis() - last >= 33) {          // ≈ 30 FPS
    last = millis();
    gui.clear();
    /* ... рисуем ... */
    gui.update();
  }
}
```

Анимации (`ProgressBar`, положение объектов в примере 2) считаются от `millis()`, поэтому их скорость не зависит от FPS.

Прочая нагрузка: `fillRect`/`hLine` — побайтовые маски по страницам (быстрые); текст размера 1 — две операции на столбец глифа; `fillCircle`/`fillRoundRect` — по одной `fillRect` на строку.

## 10. Конфигурация

Все параметры — в `EmbeddedGUI_Config.h`.

|---|---|---|

## 11. Платформы

Библиотека использует только `Arduino.h`, `Wire.h` и стандартные `pgm_read_byte`/`F()`. Ядро кода ограничено C++11 (стандарт avr-gcc в Arduino).

| Платформа | Замечания |
|---|---|
| **Arduino Uno / Nano / Pro Mini** (ATmega328P) | Основная цель. SDA = A4, SCL = A5. Буфер 1 КБ — половина ОЗУ: объявляйте `gui` глобально, строки через `F()`. |
| **Mega 2560** | SDA = 20, SCL = 21. Без особенностей. |
| **ESP32** | Свои пины: `Wire.begin(SDA, SCL); gui.begin(false);` |
| **ESP8266** | `Wire.begin(SDA, SCL); gui.begin(false);` (по умолчанию D2/D1). Вызывайте `update()` регулярно, чтобы не ловить WDT. |
| **STM32 (Arduino core)** | Через `Wire`; при необходимости `Wire.setSDA/ setSCL` до `begin(false)`. |
| **RP2040 (arduino-pico)** | `Wire.setSDA(..); Wire.setSCL(..); gui.begin(false);` |

## 12. Ограничения

* **Только монохромные дисплеи**, формат страниц SSD1306/SH1106. Режим RGB565 из v1 удалён ради простоты и памяти (цветные TFT потребовали бы 32 КБ буфера и конвертации).
* Из коробки **только I2C** (SSD1306/SH1106, до 128×64). Для SPI напишите бэкенд (см. [§8.3](#83-свой-бэкенд-spi-другой-контроллер), 15–20 строк).
* **Шрифт только ASCII (32..126)**, один размер 5×7 с целочисленным масштабированием. Кириллицы нет: символы вне диапазона выводятся как `?`. Для кириллицы/иконок используйте `bitmap()` с собственными глифами из PROGMEM либо расширьте `EGUI_Font5x7.h`.
* События ввода обрабатываются в `loop()` (очередь событий и вызов из ISR убраны ради экономии ОЗУ).
* `ProgressBar` работает с диапазоном `int16_t`.
* Один виджет может принадлежать только одному `Screen` (список встроен в виджет).
* Нет вывода с альфа-каналом, поворота на произвольный угол и т.п.

## 14. FAQ и диагностика

**Чёрный экран.** `begin()` вернул `false`? Проверьте провода и адрес (0x3C/0x3D, сканер I2C). Убедитесь, что питание 3.3 В/5 В соответствует модулю. Для SH1106-модулей укажите `EGUI_SH1106`.

**Мусор/«снег» на экране.** Скорее всего, вы используете SH1106 как SSD1306 (или наоборот): задайте правильный `EGUI_Chip`. Если мусор появляется после долгой работы или помех, вызовите `gui.invalidate(); gui.update();`.

**Картинка перевёрнута.** `gui.setFlipped(true);` после `begin()`.

**Смещение на 2 пикселя (SH1106).** `gui.driver().setColumnOffset(0)` или `2`.

**Скетч не помещается/ОЗУ мало (Uno).** Используйте `F()` для всех строк, `128×32`, уменьшите `EGUI_LABEL_CAPACITY`. «Global variables use …» должно быть заметно меньше 2048; ориентир — оставить ≥ 300–400 байт на стек.

**Нестабильность/зависания на Uno.** Классический признак нехватки ОЗУ (стек наезжает на данные). Проверьте отчёт компилятора по ОЗУ, не объявляйте `gui` внутри функций.

**Текст не рисуется.** Координаты `y` — верхний край символа (ячейка 8 пикселей высотой). Для `text` вне экрана (отрицательные координаты) отсекается безопасно. Кириллица не поддерживается.

**Медленно.** Смотрите `gui.lastFlushMicros()`; убедитесь, что частота I2C 400 кГц (`EGUI_I2C_CLOCK`), а `Wire.setClock` не перезаписывается в другом месте скетча.

**На ESP32 нужны другие пины I2C.**
```cpp
Wire.begin(SDA_PIN, SCL_PIN);
gui.begin(false);
```

## 15. Что и как проверено

Железа (Uno/ESP/OLED) и компилятора `avr-gcc` в среде, где писался код, не было. Поэтому проверено следующее, и **только на хосте** (`extras/host_test`, запуск `sh run.sh`, нужен `g++`):

* код компилируется как `-std=gnu++11 -Wall -Wextra` без предупреждений (стандарт avr-gcc в Arduino);
* **сверка с эталонной моделью:** 3000 случайных операций `pixel/fillRect/vLine` со всеми цветами (включая `INVERT`) и выходом за границы совпали с побитовой моделью;
* эмулятор SSD1306/SH1106 за интерфейсом `Wire` с 32-байтным буфером как на AVR: команды разбираются, данные попадают в «видеопамять» эмулятора; содержимое эмулятора побайтово совпадает с буфером холста; переполнений буфера Wire нет;
* чистый кадр не вызывает обмена по шине, изменение одной точки отправляет ровно одну страницу (128 байт);
* форматирование чисел (`0`, отрицательные, `-0.0`, дробные, огромные значения);
* визуальная проверка шрифта (все 95 символов), примитивов, инверсии, виджетов;
* все три примера собираются; пример 3 прогнан со сценарием нажатий (открыть настройки → изменить контраст → фокус → назад), в том числе проверено, что команда контраста доходит до дисплея.

**Не проверено:** реальное железо, фактическая скорость I2C, фактические размеры ОЗУ/флеша на AVR, поведение конкретных версий `Wire` на ESP/STM32/RP2040, SH1106 на реальном модуле (команды выбраны по документации и практике драйверов). Сообщайте о расхождениях с реальными платами: числа в [§4](#4-модель-памяти) и [§9](#9-производительность-и-частота-кадров) — расчётные.
